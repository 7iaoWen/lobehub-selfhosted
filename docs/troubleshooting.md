# 排障记录

> 按时间顺序记录部署过程中遇到的关键问题。每个案例采用「现象 → 定位 → 根因 → 方案 → 经验」五要素，是本项目最有价值的沉淀。

## 1. 文件上传报「CORS 配置错误」

- **现象**：上传 txt/图片时提示「网络异常或跨域配置不正确」，文件卡在输入框
- **定位**：F12 Network 发现预签名 PUT 请求的 host 是 `minio:9000`（容器内网名），浏览器无法解析；Console 显示「CORS 请求未能成功，状态码 null」
- **根因**：LobeHub 生成预签名上传 URL 时，host 取自 `S3_ENDPOINT` 而非 `S3_PUBLIC_DOMAIN`。后者只影响读取，不影响上传
- **解决方案**：将 `S3_ENDPOINT` 与 `S3_PUBLIC_DOMAIN` 统一为浏览器可达的公网地址
- **经验**：「CORS 报错」常是网络层问题的伪装。看到「状态码 null」基本可判定请求根本没到达服务器，真正要看的是请求的 host 是否可达

## 2. 知识库检索不到内容

- **现象**：文件能传进知识库，但对话中检索无结果
- **根因**：① 数据库向量列固定 1024 维，换用非 1024 维的 embedding 模型会导致写入/检索失败；② 检索前必须在对话中挂载知识库
- **解决方案**：选用 1024 维的 embedding 模型（如智谱 embedding-2），并确认知识库已挂载到当前对话
- **经验**：RAG 链路里「维度一致」是硬约束，换模型先核维度

## 3. 技能市场 / 云沙箱报 MARKET_AUTH_REQUIRED

- **现象**：技能市场搜索 unauthorized，云沙箱执行命令报 MARKET_AUTH_REQUIRED
- **定位**：日志显示 `[MarketAuth] No refresh token available`，说明授权从未成功
- **根因**：实例以明文 HTTP 访问，处于非安全上下文，`crypto.subtle` 为 undefined，OAuth PKCE 流程无法生成 code_verifier
- **解决方案**：引入 HTTPS 使页面进入 secure context（`crypto.subtle` 只在 https / localhost 下可用）
- **经验**：前端授权类功能失败时，先在 Console 跑 `typeof crypto.subtle` 判断是否处于安全上下文

## 4. OAuth 登录被掐断（ERR_CONNECTION_CLOSED）

- **现象**：市场登录在 token 交换阶段连接被关闭
- **根因**：跨境代理中断了 OAuth 的 token 交换连接
- **解决方案**：将 `*.lobehub.com` 加入代理直连规则
- **经验**：OAuth 回调链路对中间设备很敏感，排查时优先怀疑代理/防火墙

## 5. 部分网络访问提示「需要备案」

- **现象**：手机流量可访问，但电信家宽/部分网络被拦截，提示需要备案
- **根因**：内地服务器对未备案域名（80/443 及部分路径）做合规拦截
- **解决方案**：完成 ICP 备案 + 443 端口收口；过渡期用非标端口
- **经验**：内地部署时「域名可用性」与「备案」强绑定，架构规划阶段就要考虑备案周期

## 6. 云服务器下载依赖失败

- **现象**：apt / docker pull 超时失败
- **根因**：服务器 IPv6 路由异常，部分请求走 IPv6 失败
- **解决方案**：强制 IPv4（调整 `gai.conf` 优先级）+ 配置腾讯云镜像加速
- **经验**：服务器网络问题先看 IPv4/IPv6 路由，再看 DNS 和镜像源
